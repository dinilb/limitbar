## 1. Feasibility verdict

### Codex — **Feasible. Recommended path: local `codex app-server` JSON-RPC.**

`codex app-server` exposes an `account/rateLimits/read` JSON-RPC method that returns the current
ChatGPT/Codex rate-limit snapshot. The client process never sees a token: `codex` holds the OAuth
material in `$CODEX_HOME/auth.json`, performs its own refresh, and returns only derived numbers.

Verified live on this machine (raw response, verbatim, secrets-free by construction):

```json
{"id":2,"result":{
  "rateLimits":{
    "limitId":"codex","limitName":null,
    "primary":{"usedPercent":83,"windowDurationMins":43200,"resetsAt":1788700645},
    "secondary":null,
    "credits":{"hasCredits":false,"unlimited":false,"balance":null},
    "individualLimit":null,"spendControlReached":false,
    "planType":"free","rateLimitReachedType":null},
  "rateLimitsByLimitId":{"codex":{ ...same... }},
  "rateLimitResetCredits":{"availableCount":0,"credits":[]}}}
```

Confidence is high because the **response shape is machine-generated by the vendor**. `codex
app-server generate-json-schema --out DIR` emits JSON Schema straight from the installed binary, so
the contract can be re-derived on any machine at any version rather than guessed. See §2.1.

Caveat: `codex app-server` is labelled `[experimental]` in `codex app-server --help`, so method names
and field names may change between CLI releases. The schema generator is the mitigation, not a
guarantee.

### Claude Code — **Feasible, but on an undocumented first-party endpoint. Read-only, no refresh.**

`GET https://api.anthropic.com/api/oauth/usage` with the Claude Code OAuth access token returns
current window utilisation and reset times. Verified live, HTTP 200 (see §2.2 for the full body).

Two independent pieces of evidence that this is a genuine first-party Claude Code endpoint and not a
community invention:

1. The literal path `/api/oauth/usage` appears in the shipped official Claude Code binary
   (`~/.local/share/claude/versions/2.1.224`, Mach-O arm64), alongside `/api/oauth/profile`,
   `/api/oauth/validate`, `/api/oauth/claude_cli/roles`.
2. The request succeeds only with the `anthropic-beta: oauth-2025-04-20` header that Claude Code
   itself sends.

It is nevertheless **absent from Anthropic's public API documentation**, so it is classified
*undocumented-but-first-party*, not *official*. It is subject to change without notice and is known
to rate-limit aggressively (§5.3).

Hard constraint adopted: **we read the existing token and never refresh it.** Refreshing would mutate
`Claude Code-credentials` in the login keychain and could race Claude Code itself. If the access
token is expired we report `auth_expired` and tell the user to run `claude` once.

### Explicitly rejected

| Rejected source | Why |
|---|---|
| `chatgpt.com/backend-api/wham/usage` (used by CodexBar) | Requires lifting the raw OAuth access token out of `~/.codex/auth.json` and sending it ourselves. The app-server path gets the same data with zero token handling. |
| Browser-cookie scraping of `chatgpt.com/codex/settings/usage` (CodexBar optional mode) | Reads Safari/Chrome/Firefox cookie stores — a large, unnecessary credential-access surface. |
| "Claude relay" provider (in `nathan1658/codex-usage-menubar`) | Points at an arbitrary user-configured third-party HTTP endpoint. Directly violates the "first-party endpoints only, no third-party backend" constraint. **Not implemented.** |
| Local `~/.claude/**/*.jsonl` / `~/.codex/sessions/**/*.jsonl` cost reconstruction (ccusage-style) | Estimates spend from transcripts; it does not report subscription *quota* state, drifts from the server's own accounting, and requires reading full conversation content. |
| Refreshing either provider's OAuth token ourselves | Mutates credentials. Out of scope by instruction. |

**Authoritative schema, generated on this machine** (`codex app-server generate-json-schema --out /tmp/codex-schema`):

- `v2/GetAccountRateLimitsResponse.json` — required: `rateLimits`; optional `rateLimitsByLimitId`, `rateLimitResetCredits`.
- `RateLimitWindow` — required `usedPercent` (`int32`); optional `resetsAt` (`int64`, **Unix seconds**), `windowDurationMins` (`int64`).
- `RateLimitSnapshot` — `limitId`, `limitName`, `primary`, `secondary`, `credits`, `individualLimit`, `spendControlReached`, `planType`, `rateLimitReachedType`.
- `PlanType` enum — `free, go, plus, pro, prolite, team, self_serve_business_prolite, self_serve_business_usage_based, business, ent26, enterprise_cbp_automation, enterprise_cbp_usage_based, enterprise, edu, unknown`.
- `ClientRequest.json` lists the full account method set: `account/read`, `account/rateLimits/read`, `account/usage/read`, `account/login/start`, `account/login/cancel`, `account/logout`, `account/rateLimitResetCredit/consume`, `account/sendAddCreditsNudgeEmail`, `account/workspaceMessages/read`.

**Critical correction to the reference implementation.** `nathan1658/codex-usage-menubar`
(`Sources/UsageCore/UsageCore.swift:229-232`, commit `2385e68`) hard-codes `primary → 5-hour` and
`secondary → weekly`. That is wrong in general. On this machine `primary.windowDurationMins` is
**43200 minutes (30 days)** and `secondary` is `null`, because the account is `planType: "free"`.
Rendering that as "5h 17%" would be a straightforward lie. **Window identity must be derived from
`windowDurationMins`, not from field position.** Our implementation classifies windows by duration
and keeps the raw duration in the output.

Three consequences for the implementation:

1. **`limits[]` is the forward-compatible field.** It is a self-describing array
   (`kind`/`group`/`percent`/`resets_at`) that already carries `weekly_all` and would carry
   `weekly_opus` etc. without a code change. `five_hour`/`seven_day` are the legacy flat mirrors.
   We parse `limits[]` first and fall back to the flat fields.
2. **`utilization` scale is ambiguous across accounts.** Here it is 0–100 (`27.0`). Other reports
   show 0–1 fractions. The reference repo infers scale heuristically
   (`UsageCore.swift:264-279`). We keep an equivalent inference but prefer `limits[].percent`, which
   is unambiguously an integer percent.
3. **The payload contains billing data** (`spend`, `extra_usage`, currency, amounts). It is not a
   credential but it is sensitive. Our normalised output **omits it by default** and exposes it only
   behind an explicit `--include-spend` flag.

## 3. Recommended architecture

**One credential-touching component.** The Python CLI is the only thing that reads a secret. The
Swift app and the widget never link a credential API, never read the keychain, and make no network
requests — the app shells out to `ai-usage --json`, the widget reads a file the app wrote. This makes
the auditable surface a few hundred lines of Python instead of two codebases.

```
                    reads keychain + calls provider endpoints
                    ┌───────────────────────────────────────┐
                    │            Python CLI                  │
                    │  ai_usage/                             │
                    │    secrets.py    Secret wrapper        │  ← only module that
                    │    credentials.py keychain / file / env│    ever holds a token
                    │    providers/codex.py   (subprocess)   │
                    │    providers/claude.py  (HTTPS)        │
                    │    model.py      normalized snapshot   │
                    │    cache.py      last-good snapshot    │
                    │    cli.py        argparse + JSON out   │
                    └───────────────┬───────────────────────┘
                                    │ stdout: normalized JSON (never secrets)
              ┌─────────────────────┴────────────────────────┐
              │                                              │
   ┌──────────▼───────────┐                     ┌────────────▼─────────────┐
   │  AIUsageMenuBar.app  │  writes snapshot →  │  AIUsageWidget.appex     │
   │  (AppKit + SwiftUI)  │  ~/Library/App…/    │  (WidgetKit, sandboxed)  │
   │  spawns the CLI      │  + widget container │  reads snapshot file only│
   └──────────────────────┘                     └──────────────────────────┘
              │                                              ▲
              └── WidgetCenter.reloadAllTimelines() ─────────┘
   ┌──────────────────────┐
   │  AIUsageCore (lib)   │  decodes the CLI JSON; shared by app + widget; no I/O
   └──────────────────────┘
```

**Layer responsibilities**

1. **Credential access** (`credentials.py`) — resolution order per provider, returns a `Secret`
   object whose `__str__`/`__repr__`/`__format__` are `"<redacted>"`. Codex needs no credential at
   all on our side.
2. **Provider clients** (`providers/*.py`) — one module per provider, each declaring its allowed
   network destination as a module constant so the audit is a `grep`.
3. **Normalisation** (`model.py`) — provider-agnostic snapshot; windows are a list, not two fixed
   slots, so `weekly_opus`/30-day/etc. survive without schema churn.
4. **CLI** (`cli.py`) — `--json` (default), exit codes for automation, `--timeout`, `--provider`,
   `--no-cache`, `--include-spend`.
5. **Swift UI** — `AIUsageCore` decodes the same JSON; menu bar renders a compact grid; widget renders
   small/medium/large families.

**Refresh cadence.** Default 300 s, jittered, with a shared on-disk last-good cache so the menu bar,
the widget and any agent invocation coalesce onto one upstream call instead of three.

## 4. Proposed token-safe JSON schema

Design rules: no field ever carries a credential; every field is either a number, a timestamp, an
enum, or a short human string; unknown upstream fields are dropped rather than passed through
verbatim (so a future upstream field cannot smuggle a secret into our output).

```json
{
  "schema_version": 1,
  "generated_at": "2026-08-07T16:41:12Z",
  "ok": true,
  "providers": [
    {
      "provider": "codex",
      "status": "ok",
      "plan": "free",
      "source": "codex-app-server",
      "fetched_at": "2026-08-07T16:41:12Z",
      "stale": false,
      "windows": [
        {
          "key": "monthly",
          "label": "30d",
          "window_minutes": 43200,
          "used_percent": 83,
          "remaining_percent": 17,
          "resets_at": "2026-09-06T13:17:25Z",
          "resets_in_seconds": 2500000
        }
      ],
      "credits": {"has_credits": false, "unlimited": false},
      "notes": ["secondary window not reported by upstream"],
      "error": null
    },
    {
      "provider": "claude",
      "status": "ok",
      "plan": "max",
      "source": "anthropic-oauth-usage",
      "fetched_at": "2026-08-07T16:41:12Z",
      "stale": false,
      "windows": [
        {"key": "five_hour", "label": "5h", "window_minutes": 300,
         "used_percent": 27, "remaining_percent": 73,
         "resets_at": "2026-08-07T21:20:00Z", "resets_in_seconds": 16728},
        {"key": "weekly_all", "label": "7d", "window_minutes": null,
         "used_percent": 44, "remaining_percent": 56,
         "resets_at": "2026-08-11T05:00:00Z", "resets_in_seconds": 304728}
      ],
      "credits": null,
      "notes": [],
      "error": null
    }
  ],
  "tightest": {"provider": "claude", "window_key": "five_hour", "remaining_percent": 73}
}
```

`status` ∈ `ok | unknown | auth_missing | auth_expired | rate_limited | offline | upstream_error | unsupported`.
`error` is `{ "code": <status>, "message": "<short, redacted>" }` or `null`.
`tightest` is the single number an automation agent should gate on.

Exit codes: `0` all requested providers `ok`; `1` at least one non-`ok`; `2` bad invocation.
`--json` always prints a complete document on stdout even when everything failed, so a consumer can
always parse rather than branch on exit code alone.

## 5. Failure behaviour

| Condition | Detection | Behaviour |
|---|---|---|
| **5.1 No credential** | keychain item absent, no `~/.claude/.credentials.json`, no env var | `status: auth_missing`, `message: "Claude Code credentials not found; run: claude"`. Never names the searched key material. |
| **5.2 Expired auth** | `claudeAiOauth.expiresAt` (ms) in the past, or HTTP 401 | `status: auth_expired`, `"run claude once to refresh"`. **We never refresh** — refreshing would mutate the keychain item and could race Claude Code. |
| **5.3 Rate limited** | HTTP 429 (see `claude-code#31021`) | `status: rate_limited`; honour `Retry-After` when present; serve the cached last-good snapshot with `stale: true`; exponential backoff with jitter; the app's poll interval is floored at 60 s. |
| **5.4 Offline** | DNS/connect failure, timeout | `status: offline`; serve cache with `stale: true` and `fetched_at` from the cache. Codex still works offline? No — `codex` itself needs the network, so it reports `offline` too. |
| **5.5 Upstream schema change** | required key missing / type mismatch | Parse defensively: every field optional, unknown `limits[].kind` values are passed through as generic windows. If nothing parses, `status: upstream_error` with the *shape* of the problem (`"unrecognised usage payload"`), never the payload body — the body may contain account data. |
| **5.6 Codex binary missing** | resolution order exhausted | `status: unsupported`, `"codex CLI not found"`. |
| **5.7 Codex app-server hangs** | no `id:2` response within timeout | terminate the child process (CodexBar's documented hazard), `status: upstream_error`, `"codex app-server timed out"`. |
| **5.8 Codex not logged in** | JSON-RPC error, or `requiresOpenaiAuth` | `status: auth_missing`, `"run: codex login"`. |
| **5.9 Partial success** | one provider ok, one not | top-level `ok: false`, each provider carries its own status. The document is always complete. |
| **5.10 Unknown, not zero** | any missing number | `null`, rendered as `?` in the UI. Never coerce an unknown to `0` or `100` — either would cause an automation agent to make the wrong scheduling decision. |

## 6. Build plan (milestones)

1. **M1 — model + redaction.** `Secret` wrapper, normalised dataclasses, JSON encoder, unit tests for redaction in `str`/`repr`/`format`/f-string/`json.dumps`/traceback.
2. **M2 — Codex provider.** app-server JSON-RPC over stdio, timeout + child termination, window classification by `windowDurationMins`, golden-fixture parse tests including the `secondary: null` free-plan case.
3. **M3 — Claude provider.** credential resolution (keychain → file → env), `limits[]`-first parsing with flat-field fallback, utilisation scale inference, 401/429/timeout handling.
4. **M4 — CLI surface.** argparse, exit codes, `--provider`, `--timeout`, `--include-spend`, `--no-cache`, cache read/write with `stale`.
5. **M5 — `AIUsageCore` Swift library.** Decode the CLI document; formatting helpers; tests against the same golden fixtures the Python tests use.
6. **M6 — Menu bar app.** `NSStatusItem` with a rendered compact grid, dropdown with per-provider detail and errors, manual refresh, poll timer.
7. **M7 — WidgetKit extension.** small/medium/large; snapshot file written by the app into both the normal path and the widget's sandbox container.
8. **M8 — Packaging script.** Build `.app` + `.appex`, ad-hoc codesign, `lsregister`/`pluginkit`. **No LaunchAgent.**
9. **M9 — Docs + verification.** README security model; the §7 verification suite in CI-able form.

## 7. Verification plan — proving no token escapes

| Check | Method |
|---|---|
| **V1 Redaction unit tests** | Assert a canary secret never appears in `str()`, `repr()`, `f"{s}"`, `"%s" % s`, `json.dumps(default=str)`, `logging` of the object, or a formatted traceback containing it as a local. |
| **V2 Canary end-to-end** | Inject `CLAUDE_CODE_OAUTH_TOKEN=<canary>`, force every failure path (401, 429, timeout, malformed body), assert the canary appears in neither stdout, stderr, the cache file, nor any exception text. |
| **V3 Network allow-list, static** | `grep -rn "https://"` over the Python and Swift sources; assert the only hosts are `api.anthropic.com`. Codex adds none of our own. A unit test asserts the module-level destination constants equal the allow-list. |
| **V4 Network allow-list, dynamic** | Run the CLI under a recording HTTP shim in tests; assert exactly one request, to `api.anthropic.com`, with `Authorization` present, and that no request body is sent. |
| **V5 Output schema fuzz** | Feed the normaliser payloads containing a planted secret-looking string in unexpected keys; assert it never reaches the output document (proves the drop-unknown-fields rule). |
| **V6 Swift credential-free proof** | `grep -rn "Security\|SecItem\|security\|credentials\|Bearer\|URLSession"` over `macos/Sources`; expect zero. The Swift target's only inputs are the CLI's stdout and the snapshot file. |
| **V7 Cache inspection** | After a run, dump the on-disk cache and assert it validates against the published schema and contains no field outside it. |
| **V8 No persistence side-effects** | Assert the CLI writes only under its own cache directory; assert the keychain item's modification date is unchanged after a run (proves we never refreshed). |
